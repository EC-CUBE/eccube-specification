# EA15_エージェントコマース設定_結合試験項目書

### 事前準備

対象は EC-CUBE 4.4 のエージェントコマース（ACP: Agentic Commerce Protocol / UCP: Universal Commerce Protocol）と MCP（Model Context Protocol）サーバの、管理画面の設定と運用画面。API・CLI の項目は EX01 にある。有効化の確認は curl 等の HTTP クライアントから直接エンドポイントを叩いて行う。

1. プラグイン
   1. API プラグイン（eccube-api4）の 4.4 ブランチ（https://github.com/EC-CUBE/eccube-api4/tree/4.4）をインストールし有効化する。MCP サーバの認証に必要（4.4.0-alpha-1 リリースノートの前提条件）
2. HTTPS
   1. 4.4 はセッション Cookie に `SameSite=None` を付与するため、HTTP で動かすと管理画面にログインできない。`symfony server:start` 等の HTTPS 環境で確認する（HTTP で確認する場合は `app/config/eccube/packages/framework.yaml` の `cookie_samesite: none` を `lax` に変更し `var/cache` と `var/build` を削除する）
   2. 以降のリクエスト例は `https://example.com` を店舗 URL に、`admin` を管理画面 URL（`eccube_admin_route`）に読み替える
3. 店舗設定のフラグ（いずれも初期値は無効）
   1. 設定＞店舗設定＞基本設定の「エージェントコマース」で ACP / UCP チェックアウト、「MCP サーバ」で MCP を切り替える
   2. SQL で `dtb_base_info` を直接更新した場合は `bin/console cache:pool:clear --all` を実行する（BaseInfo はキャッシュされるため、更新が反映されず 404 のままになる）
4. 環境変数（`.env`）
   1. `ECCUBE_AGENT_COMMERCE_ACP_FEED_BASE_URL` / `ECCUBE_AGENT_COMMERCE_ACP_FEED_API_KEY`: ACP プロダクトフィード push 先と Bearer キー。両方設定されるまで push は失敗する
5. テストデータ
   1. 公開中の商品に在庫数管理（在庫無制限 OFF）の規格を作り、`dtb_product_class.id`（以下 `<PRODUCT_CLASS_ID>`）を控える。`visible = 0` の規格は購入明細から除外されるため使わない
6. UCP の冪等キー（`Idempotency-Key` ヘッダ）はリクエストごとに新しい値（例: `uuidgen`）を使う。同じ値を別のリクエストに使うと conflict（409）、同じリクエストに使うと前回応答のリプレイになる

リクエスト例（UCP create。認証ヘッダ不要）

```
curl -s -X POST https://example.com/ucp/checkout-sessions \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 22222222-2222-2222-2222-222222222222' \
  -d '{
    "currency": "JPY",
    "line_items": [{"item": {"id": "<PRODUCT_CLASS_ID>"}, "quantity": 1}],
    "buyer": {"first_name": "太郎", "last_name": "山田", "email": "agent-test@example.com", "phone_number": "0312345678"},
    "fulfillment": {"destinations": [{"first_name": "太郎", "last_name": "山田", "postal_code": "1000001", "address_region": "東京都", "address_locality": "千代田区", "street_address": "1-1-1", "phone_number": "0312345678"}]}
  }'
```

## EA1501-UC01-T01_店舗設定の表示

1. 管理画面にログインし、設定＞店舗設定＞基本設定を表示する
2. 「エージェントコマース」カードに説明文「AIエージェント (ChatGPT / Gemini 等) 経由のチェックアウトを有効化します。Discovery / カタログは常時公開され、ここでは checkout のみを制御します。checkout は日本未提供のため、通常は無効のままにしてください。」と、「ACP チェックアウトを有効にする」「UCP チェックアウトを有効にする」のトグルが表示されることを確認する
3. 「MCP サーバ」カードに説明文「AI クライアント（Claude Desktop / Cursor 等）が管理データを参照する MCP サーバ（^/admin/mcp）を有効化します。読み取り専用です。既定は無効で、無効の間はエンドポイントを 404 で塞ぎます。利用には API プラグイン（api44）が有効で、OAuth2 トークンを発行済みである必要があります。」と、「MCP サーバを有効にする」のトグルが表示されることを確認する
4. インストール直後は 3 つのトグルがすべて OFF であることを確認する

## EA1501-UC01-T02_ACPチェックアウトの有効化

1. ACP チェックアウトが OFF の状態で `curl -s -o /dev/null -w '%{http_code}' https://example.com/.well-known/acp.json` を実行し、404 が返ることを確認する
2. 設定＞店舗設定＞基本設定で「ACP チェックアウトを有効にする」を ON にして登録する
3. 再度 `/.well-known/acp.json` を取得し、200 が返ることを確認する
4. 「ACP チェックアウトを有効にする」を OFF に戻して登録し、404 に戻ることを確認する

## EA1501-UC01-T03_UCPチェックアウトの有効化

1. UCP チェックアウトが OFF の状態で事前準備の UCP create リクエストを送り、404 が返ることを確認する
2. 「UCP チェックアウトを有効にする」を ON にして登録する
3. 再度 UCP create を送り、201 でセッションが作成されることを確認する
4. OFF に戻して登録し、作成済みセッションの `GET /ucp/checkout-sessions/<SESSION_ID>` も 404 になることを確認する

## EA1501-UC01-T04_MCPサーバの有効化

1. MCP が OFF の状態で `curl -s -D - -X POST https://example.com/admin/mcp -H 'Content-Type: application/json' -d '{}'` を実行し、404 かつ空ボディ（管理画面の HTML 404 ページではない）が返ることを確認する
2. 同じリクエストを `Content-Type: text/plain` で送っても 415 ではなく 404 が返ることを確認する（無効時はエンドポイントの存在を秘匿する）
3. 「MCP サーバを有効にする」を ON にして登録する
4. 手順 1 のリクエストを再送し、401 と `WWW-Authenticate` ヘッダ（`resource_metadata=` と `/.well-known/oauth-protected-resource` を含む）が返ることを確認する
5. OFF に戻して登録し、404 に戻ることを確認する

## EA1501-UC01-T05_エージェントコマース運用画面の表示

1. 管理画面のコンテンツ管理メニューに「エージェントコマース」が表示されることを確認する
2. コンテンツ管理＞エージェントコマースを開き、上部に警告「この機能は日本国内では未提供です。検証目的に限定してご利用ください。」が表示されることを確認する
3. 「ACP プロダクトフィード (push)」カードに説明文、「フィード ID」入力欄（placeholder `feed_xxxxx`）、「今すぐ push (差分)」「全置換 push」ボタンが表示されることを確認する
4. 「UCP カタログ (pull)」カードに説明文「UCP カタログ API のキャッシュを操作します。カタログは常時公開されます。」、「カタログ API」の「公開中」バッジ、「キャッシュ生成」「キャッシュクリア」ボタンが表示されることを確認する

## EA1501-UC01-T06_ACPフィードpush_フィードID未入力

1. コンテンツ管理＞エージェントコマースで「フィード ID」を空のまま「今すぐ push (差分)」を押す
2. エラー「フィード ID を入力してください。」が表示され、同じ画面に戻ることを確認する
3. 「全置換 push」でも同じエラーになることを確認する

## EA1501-UC01-T07_ACPフィードpush_認証情報未設定

1. `ECCUBE_AGENT_COMMERCE_ACP_FEED_BASE_URL` と `ECCUBE_AGENT_COMMERCE_ACP_FEED_API_KEY` が未設定であることを確認する
2. 「フィード ID」に任意の文字列を入力し「今すぐ push (差分)」を押す
3. エラー「push の送信に失敗しました。設定を確認してください。」が表示されることを確認する
4. 「全置換 push」でも同じエラーになることを確認する
5. `var/log/<環境>/` のログに `ACP Feed push (differential) failed.` / `ACP Feed push (full replacement) failed.` が記録され、API キーの値が含まれていないことを確認する

## EA1501-UC01-T08_UCPカタログキャッシュの生成とクリア

1. コンテンツ管理＞エージェントコマースで「キャッシュ生成」を押し、「カタログキャッシュを生成しました。」が表示されることを確認する
2. `var/runtime/<環境>/agent-commerce/catalog/` 配下にキャッシュファイルが生成されていることを確認する
3. 「キャッシュクリア」を押し、「カタログキャッシュをクリアしました。」が表示されることを確認する
