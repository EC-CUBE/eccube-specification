# EA13_読み取り専用モード_結合試験項目書

4.3 までの `ECCUBE_RESTRICT_FILE_UPLOAD` の試験項目（EA06 の「ファイルアップロード制限」系 EA0602-UC01-T10 / EA0603-UC01-T04 / EA0604-UC01-T04 / EA0606-UC01-T02 / EA0607-UC01-T02、EA11 の EA1102-UC01-T05 / EA1103-UC01-T01）は本章に統合する。4.4 では対象画面を 403 で閉ざす挙動から、内容は表示したまま保存操作だけを無効化する読み取り専用モードへ変わる。保存操作の代わりに使う CLI の項目は EX02 にある。

関連 Issue / PR: [EC-CUBE/ec-cube#7072](https://github.com/EC-CUBE/ec-cube/issues/7072)（親 Issue）、#7098 / #7100 / #7105 / #7114 / #7117 / #7119 / #7121 / #7124 / #6959

### 事前準備

#### 読み取り専用モードの有効化

`.env` に次を追加する。値は `%env(ECCUBE_RESTRICT_FILE_UPLOAD)%` としてリクエストごとに解決されるため、ビルドディレクトリの再生成は不要で、次のリクエストから反映される。

```
ECCUBE_RESTRICT_FILE_UPLOAD=1
```

無効に戻すときは `0` にする。

OS の環境変数で渡す構成では次の点に注意する。

- `APP_ENV` を OS の環境変数で渡さない構成では、CLI・Web とも `.env` の値が OS の環境変数より優先される
- OS の環境変数で `APP_ENV` を渡す構成（docker 構成等）では、CLI（`bin/console`）は `.env` を読み込まず、OS の環境変数の値だけを使う
- Web は `.env` を読み込むが、OS の環境変数として PHP の `$_SERVER` に届いているキーは上書きしない。Apache（mod_php）では `PassEnv` に無い環境変数は `$_SERVER` に入らないため、`.env` に同じキーがあると Web 側では `.env` の値が使われる。docker 構成の `PassEnv`（`dockerbuild/docker-php-entrypoint`）には `ECCUBE_RESTRICT_FILE_UPLOAD` が含まれないため、compose の `environment:` で渡すときは `.env` に同じキーを書かない
- php-fpm の `env[...]` 等で渡す構成では、Web サーバーのプロセス環境に届いていることを確認する

#### 権限分離構成（Web サーバーと CLI を別ユーザーにする）

本体リポジトリの `docker-compose.permission-lanes.yml` を重ねて起動する（`.github/workflows/permission-lanes-test.yml` と同じ構成）。

- `--build` は必須。公開イメージには権限分離のエントリポイントが含まれない
- DB は PostgreSQL または MySQL が必須。SQLite は Web と CLI の双方が同じファイルへ書くため起動を中止する
- 分離モードは `APP_ENV=prod` 固定。prod のセッション cookie は `SameSite=None` のため HTTP では管理画面にログインできない。HTTPS（自己署名、ポート 4430）でアクセスする
- `ECCUBE_RESTRICT_FILE_UPLOAD=1`、`ECCUBE_CLI_LOG_TO_FILE=0`、`ECCUBE_MAINTENANCE_FILE_PATH=/var/www/html/var/runtime/.maintenance`（絶対パス）は compose ファイル側で設定済み

```
docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.pgsql.yml -f docker-compose.permission-lanes.yml up -d --build
```

起動後、アクセスを受ける前にビルドディレクトリを生成する。

```
docker compose exec -u <CLI_USER> ec-cube bin/console eccube:cache:build
```

CLI ユーザー名（`<CLI_USER>`）は `composer.json` の所有者 uid を `getent passwd <uid>` で引く。既定では `eccube`（uid はホストユーザーに合わせる）。Web サーバーは `www-data`（uid 33）のまま。CLI のコマンドは CLI ユーザーで実行し、docker 構成では `docker compose exec -T -u <CLI_USER> ec-cube` を前置する。

#### 後片付け

```
docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.pgsql.yml -f docker-compose.permission-lanes.yml down -v
sudo chown -R <UID>:<GID> html/upload
```

## EA1302-UC01-T04_セキュリティ管理（一部キーが OS 環境変数で上書き）

Apache（mod_php）構成では、`.env` から対象キー（`ECCUBE_FORCE_SSL`、手順 6 では `ECCUBE_ADMIN_ROUTE`）の行を削除しておく。`PassEnv` に無い環境変数は `$_SERVER` に入らないため、`.env` に行があると Web 側では `.env` の値が使われ、上書きとして検出されない。

1. Web サーバーのプロセス環境変数に `ECCUBE_FORCE_SSL=0` を設定して起動する（docker 構成では `environment:` に追加）
1. セキュリティ管理を表示すると「この設定の環境変数（ECCUBE_FORCE_SSL）が OS のプロセス環境変数またはカスケードファイル（.env.local 等）で上書きされているため、.env への変更は反映されません。…」の警告が表示される。「登録」ボタンは有効
1. SSL 強制を ON にし、あわせて管理画面許可 IP を変更して登録する
1. 「保存しました」と、上書きされているキー名を含む警告が表示される
1. `.env` の `ECCUBE_ADMIN_ALLOW_HOSTS` は書き換わり、`ECCUBE_FORCE_SSL` は書き換わらない
1. `ECCUBE_ADMIN_ROUTE` を環境変数で上書きした状態で管理画面 URL を変更して登録すると、`.env` の `ECCUBE_ADMIN_ROUTE` は書き換わらず、ログアウトも発生しない

## EA1302-UC01-T05_テンプレート設定（ECCUBE_TEMPLATE_CODE が上書き）

Apache（mod_php）構成では、EA1302-UC01-T04 と同じ理由で `.env` から `ECCUBE_TEMPLATE_CODE` の行を削除しておく。

1. Web サーバーのプロセス環境変数に `ECCUBE_TEMPLATE_CODE=default` を設定して起動する
1. オーナーズストア → テンプレート → テンプレート一覧 を表示する
1. 「この設定の環境変数（ECCUBE_TEMPLATE_CODE）が … 上書きされているため、.env への変更は反映されません。」の警告が表示され、「登録」ボタンが無効化されている
1. POST で別テンプレートの選択を送る
1. 「保存に失敗しました」と上記の理由がエラー表示され、`.env` の `ECCUBE_TEMPLATE_CODE` は変更されない
1. `.env.local.php` が存在する場合、`.env` が書き込み不可の場合も同様に「登録」ボタンが無効化され、保存が拒否される

## EA1302-UC01-T06_反映可能な環境では警告が出ない

1. `.env` が存在し書き込み可能、`.env.local.php` が無く、対象キーがプロセス環境変数で上書きされていない状態にする
1. セキュリティ管理とテンプレート一覧を表示する
1. `.env` に関する警告は表示されず、「登録」ボタンは有効
1. 設定を変更して登録すると「保存しました」が表示され、`.env` に反映される
