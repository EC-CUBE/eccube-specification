# EF10_返品申請_結合試験項目書

### 事前準備

対象機能: [EC-CUBE/ec-cube#6838](https://github.com/EC-CUBE/ec-cube/pull/6838)

- 会員A・会員B の 2 会員を登録し、ログインできる状態にしておく
- 会員A で商品P（返品可。`dtb_product.refund_allowed` は既定で true）を数量 2 で購入し、管理画面の受注編集で対応状況を「発送済み」に変更する（以下「対象受注」）
- 会員A で別の受注を作成し、対応状況を「新規受付」のままにしておく（以下「未発送受注」）
- 返品不可商品Q を用意する。管理画面に設定項目はないため DB で `UPDATE dtb_product SET refund_allowed = false WHERE id = <商品QのID>;` を実行し、会員A で商品Q を購入した受注を「発送済み」にしておく
- PHP の `upload_max_filesize` と `post_max_size` を 32M など、16M より十分大きい値に設定する（15MB 超ファイルの試験で PHP 側の制限に先に掛からないようにするため。PHP の `16M` は 16,777,216 バイトで、`post_max_size` にはフォームのほかの項目の分も含まれる）。Apache（mod_php）では EC-CUBE ルートの `.htaccess` にある `php_value post_max_size 10M` / `php_value upload_max_filesize 10M` が php.ini より優先されるため、`.htaccess` の値も同じく書き換える
- 添付用ファイルを用意する: JPEG / PNG / GIF / WebP の画像、MP4 / MOV / AVI の動画、15,000,000 バイトを超える GIF 画像（例: 16MB）、許可外形式のファイル（.txt / .pdf）
- 添付ファイルの直リンク試験（EF1001-UC03-T03）は Apache 環境で実施する（`html/upload/refund_request/.htaccess` による拒否）
- エラー画面の文言（「アクセスできません。」「ページがみつかりません。」など）を確認する項目は `APP_ENV=prod` で実施する（`APP_ENV=dev` ではエラー画面のテンプレートが使われず、Symfony のデバッグ用画面が表示される）
- 管理画面の返品申請管理・通知メールは EA14、一時ファイルの掃除コマンドは EX0204 で確認する

## EF1001-UC01-T09_返品申請（WebP・GIF・MOV・AVI の添付）
添付ファイルの形式は、拡張子ではなくファイルの内容から判定した MIME タイプで検査する（MOV は `video/quicktime`、AVI は `video/x-msvideo`）。内容からの判定はサーバーの libmagic に依存するため、MOV・AVI が形式エラーになった場合は、まずサーバーの PHP での判定結果（`php -r "echo mime_content_type('<ファイル>');"`）を確認する。

1. TOPページ(会員Aでログイン状態)→マイページ→ご注文履歴→対象受注の[詳細を見る]→商品Pの[返品申請]
1. 返品希望数量・返品理由を入力し、証拠ファイルに WebP 画像・GIF 画像・MOV 動画の 3 件を選択して[確認画面へ]ボタンを押下する
1. 返品申請内容確認画面に遷移し、画像 2 件はサムネイル、動画 1 件は再生コントロール付きの動画欄で表示される（MOV が再生できるかはブラウザの対応形式による）
1. `html/upload/refund_request/temp/<ハッシュ名>/` 配下のファイル名の拡張子が .webp / .gif / .mov になっている
1. [戻る]ボタンを押下し、返品希望数量・返品理由を入力し、証拠ファイルに AVI 動画 1 件を選択して[確認画面へ]ボタンを押下する
1. 返品申請内容確認画面に遷移し、動画が再生コントロール付きの動画欄で表示される（AVI が再生できるかはブラウザの対応形式による）
1. `html/upload/refund_request/temp/<ハッシュ名>/` 配下が拡張子 .avi のファイル 1 件のみになっている（前回の一時ファイルは削除される）

1. DB（`dtb_order`）で当該受注の注文番号と、`dtb_order_item` で商品明細 ID を確認する
1. ブラウザのアドレスバーに `/mypage/refund_request/<注文番号>/<明細ID>` を入力してアクセスする
1. 「ページがみつかりません。」「URLに間違いがないかご確認ください。」のエラー画面が表示される
1. DB で当該受注の対応状況を決済処理中に変更する（`UPDATE dtb_order SET order_status_id = 7 WHERE id = <受注ID>;`）
1. 同じ URL に再度アクセスする
1. 「ページがみつかりません。」のエラー画面が表示される

## EF1001-UC05-T03_申請不可（他会員の受注へ直接アクセス）

1. 会員B でログインする
1. ブラウザのアドレスバーに `/mypage/refund_request/<会員Aの対象受注の注文番号>/<商品Pの明細ID>` を入力してアクセスする

1. `/mypage/refund_request/<会員Aの対象受注の注文番号>/<商品Pの明細ID>/history` にアクセスする
1. 「ページがみつかりません。」のエラー画面が表示される

## EF1001-UC05-T04_申請不可（存在しない明細・商品以外の明細へ直接アクセス）

1. TOPページ(会員Aでログイン状態)
1. ブラウザのアドレスバーに `/mypage/refund_request/<対象受注の注文番号>/999999` を入力してアクセスする
1. 「ページがみつかりません。」のエラー画面が表示される
1. 対象受注の送料明細の ID を DB（`dtb_order_item` の `order_item_type_id` が送料のもの）で確認し、`/mypage/refund_request/<対象受注の注文番号>/<送料明細ID>` にアクセスする
1. 「ページがみつかりません。」のエラー画面が表示される
